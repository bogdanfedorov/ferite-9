# Збірка Ферит-9 під Windows, Linux і веб

## Три шляхи

| | Go (`make windows`) | Electron (`npm run dist:win`) | Веб (`make web`) |
|---|---|---|---|
| Розмір | ~3 МБ, один файл | ~150 МБ, тека з файлами | ~70 КБ, один zip |
| Залежності для збірки | лише Go, cgo не потрібен | Node + npm, ~300 МБ модулів | лише Go |
| Крос-компіляція | з будь-якої ОС однією командою | кожну платформу на своїй ОС | платформи нема |
| Що потрібно гравцю | Edge або Chrome у системі | нічого | будь-який браузер |
| Вигляд | окреме вікно без браузерного обрамлення | те саме | `<iframe>` на сторінці itch |
| Захист коду | джерела видно в exe | обфускований бандл в asar | джерела видно, як у вебі завжди |

Go-збірка — для швидкої роздачі й розробки: клікнув exe, відкрилось вікно.
Electron — для Steam, бо не залежить від браузера гравця й тримає
обфускований код. Веб — для itch.io: грати прямо в браузері, нічого не качаючи.

## Шлях 1: один exe на Go

Потрібен лише [Go](https://go.dev/dl/) 1.21+. Уся гра зашита в бінарник
через `go:embed`, cgo не використовується, зовнішніх модулів нема.

```bash
make run        # запустити локально
make windows    # dist/Ferit-9.exe
make linux      # dist/ferit-9
make all        # обидві платформи
```

Без `make` (наприклад, у cmd.exe) те саме вручну:

```bash
go build -trimpath -ldflags "-s -w -H windowsgui" -o dist/Ferit-9.exe .
```

**Як це працює.** Лаунчер піднімає HTTP-сервер на `127.0.0.1` з випадковим
портом і випадковим токеном у шляху, тоді запускає Edge (або Chrome) у режимі
`--app` з окремим тимчасовим профілем: без адресного рядка, вкладок, розширень
і доступу до профілю користувача. Вікно має власну іконку й окремий значок на
панелі задач — виглядає як звичайний застосунок.

Коли вікно закривають, лаунчер гасне сам: він стежить і за процесом вікна,
і за пульсом сторінки (вона пінгує кожні 2 секунди). Тимчасовий профіль
видаляється.

Прапорець `-H windowsgui` прибирає консольне вікно. Якщо exe чомусь не
стартує, причина лягає у `ferit9-error.log` поруч із ним.

**Чого бракує гравцю.** Потрібен Chromium-браузер: на Windows 10/11 Edge
є завжди, на Linux — ні. Якщо жодного не знайдено, лаунчер відкриє гру
в типовому браузері звичайним вікном.

**Іконка в самому exe** (необов'язково, для значка у провіднику):

```bash
go install github.com/josephspurrier/goversioninfo/cmd/goversioninfo@latest
make icon && make windows
```

## Шлях 2: Electron

Головний процес (`electron/main.js`) тримає рендерер ізольованим: без Node,
без devtools у релізі. Одна копія гри на машину — Steam може запустити ярлик
повторно, і тоді фокус просто переходить на вже відкрите вікно. Гра повністю
локальна: усі запити дозволів відхиляються, нові вікна й навігація геть зі
сторінки заборонені, а в релізі перехоплюються типові гарячі клавіші інспектора.
Команди й вимоги — нижче, у розділі «Що потрібно для Electron».

## Шлях 3: веб-збірка для itch.io

Та сама гра, тільки без лаунчера: itch роздає вміст архіву як статику
й показує гру в `<iframe>`.

```bash
make web            # dist/Ferit-9-web.zip
go run ./tools/webzip   # те саме без make
```

Збірник (`tools/webzip/main.go`) складає архів так:

- `index.html` лежить **у корені** архіву — цього вимагає itch;
- усі `<script src="js/…">` склеєні в один `bundle.js` у тому ж порядку,
  в якому підключені у сторінці (список береться зі сторінки, тож
  розійтися з нею не може — на відміну від ручного списку в Node-збірнику);
- шрифти перемикаються на локальні, якщо в `fonts/` реально лежать `.woff2`;
  інакше лишається лінк на Google Fonts — на itch гра й так онлайн;
- пульсу лаунчера в архіві нема: його домішує `main.go` на льоту, а тут
  немає кого гасити.

Мініфікації й обфускації в цьому шляху нема: у вебі код усе одно
віддається браузеру як є.

**Як заливати.** На сторінці гри: Uploads → залити `Ferit-9-web.zip`,
поставити галочку **«This file will be played in the browser»**,
Kind of project → **HTML**. Далі в Embed options:

| Поле | Значення |
|---|---|
| Viewport | 1280 × 800 |
| Fullscreen button | увімкнути (гра сама переставляє canvas на `resize`) |
| Mobile friendly | вимкнути — керування на клавіатурі й миші |

Ліміт itch — 1 ГБ; архів важить ~70 КБ.

## Чесно про «без реверс-інженерингу»

**Повністю унеможливити реверс-інженеринг гри на JS/Electron не можна.**
Це не питання налаштувань — так влаштована технологія: код виконує V8
у процесі користувача, тож його завжди можна дістати з пам'яті. Те саме
стосується Unity (IL2CPP теж розбирають), Godot і будь-якого нативного рушія.
Різниця лише у вартості злому.

Що реально зроблено в цій збірці, щоб цю вартість підняти:

| Крок | Що дає | Чого не дає |
|---|---|---|
| Склейка 11 файлів в один `bundle.js` | нема структури проєкту, імен файлів | код усе ще виконуваний |
| Terser з `mangle.toplevel` | усі імена змінних і функцій втрачено | логіку видно |
| javascript-obfuscator (`stringArray`, `base64`, `selfDefending`) | рядки не шукаються грепом, beautify ламає скрипт | ~15 хвилин роботи з дебагером усе повертає |
| Пакування в `asar` | файли не лежать відкрито в теці гри | `npx asar extract` розпаковує за секунду |
| `contextIsolation`, `nodeIntegration: false`, `sandbox` | рендерер не має доступу до Node і ФС | це безпека, не захист коду |
| devtools вимкнено, F12/Ctrl+Shift+I заблоковано в релізі | випадковий гравець не відкриє інспектор | запуск із `--remote-debugging-port` обходить |

**Заплутування навмисно легке.** Агресивні режими `controlFlowFlattening`
і `deadCodeInjection` сповільнюють код у 2–5 разів, а в цій грі щокадру
обробляється до 153 600 клітинок — фізика просто не влізе в кадр.
Захист коду тут коштував би грою.

Якщо захист коду критичний, єдиний працездатний шлях — переписати симуляцію
на нативну мову (Rust/C++) і віддавати з неї лише скомпільований `.dll`/`.so`,
лишивши в JS тільки інтерфейс. Це окремий великий проєкт.

Для демо в Steam практичний захист — не обфускація, а **Steam DRM-обгортка**
(вмикається в Steamworks: App Admin → Installation → DRM) і те, що демо
все одно безкоштовне.

## Що потрібно для Electron

- Node.js 18+ (`node --version`) — на цій машині його немає, як і Go,
  тож жодну збірку я не запускав: конфіги й лаунчер написані, але перший
  запуск за тобою.
- Для Windows-збірки — Windows, для Linux-збірки — Linux або WSL.
  (electron-builder збирає Linux із Windows лише через Docker, простіше
  зібрати кожну платформу на своїй.)

## Команди

```bash
npm install
npm run fonts      # один раз: викачує шрифти в fonts/ (потрібен інтернет)
npm start          # зібрати app/ і запустити в Electron
npm run dist:win   # release/win-unpacked + інсталятор NSIS
npm run dist:linux # release/linux-unpacked + tar.gz + AppImage
```

`npm run build:app` збирає лише `app/` (bundle.js + index.html + style.css) —
саме цю теку пакує electron-builder. Список файлів у `tools/build-app.js`
ведеться вручну, і його порядок мусить збігатися з порядком `<script>`
в `index.html`.

Якщо `fonts/fonts.css` існує, збірник вшиває шрифти локально й прибирає
звернення до Google Fonts; якщо ні — попереджає в консолі й лишає онлайн-лінк.

## Що заливати в Steam

Steam хоче теку з готовою грою, а не інсталятор:

| Платформа | Тека | Launch executable |
|---|---|---|
| Windows | `release/win-unpacked/` | `Ferit-9.exe` |
| Linux | `release/linux-unpacked/` | `Ferit-9` |

Далі в Steamworks:

1. **Демо — це окремий App ID.** Створюється в App Admin основної гри
   (Edit Store Page → Basic Info → Demo). Свій депот, своя сторінка.
2. Створи два депоти (Windows + Linux), у кожному Content Root — відповідна
   тека з таблиці вище.
3. У `steam_build.vdf` (SteamPipe) вкажи депоти, збери `steamcmd +run_app_build`.
4. Launch Options: Windows → `Ferit-9.exe`, Linux → `Ferit-9`.
5. Увімкни Steam DRM-обгортку, якщо хочеш хоч якийсь бар'єр.
6. Steamworks SDK для демо не обов'язковий — гра нічого не питає в Steam.
   Знадобиться лише для досягнень чи хмарних збережень.
