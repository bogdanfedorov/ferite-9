# A1: Pickup zone as a building

Status: docs. Feedback items 1, 2, 3, 7 (A2 merged in).

## What and why

The pickup zone (the "pad") is where the drone collects cargo. Playtesters
dragged it into sand, over ore and under overhangs, then could not tell where
it was because it is drawn in the sand colour. The drone flies in from above,
so a zone under rock makes no sense either.

The pad becomes a fixed-size block, placed with one click like a building. It
can be placed only where every cell of the block is empty and the columns
above it are open to the sky. It is drawn in a colour that stands out against
sand.

## Current behaviour

- **State.** One global `cargoPad = {x, y, w, h}` in world X, `js/world.js:347`.
  `setCargoPad` converts local to world X (`world.js:349`), `padLocal` back
  (`world.js:355`), `padInWindow` checks the whole rect is inside the window
  (`world.js:364`). `finishWorld` clears it (`world.js:396`). A new pad
  replaces the old one.
- **Placement.** Registered in `js/PlayerInteract/Buildings/Pad.js:37` with
  `shapes: ['rect']`, `max: PAD_MAX` (96 cells, `Pad.js:1`), `fits:
  clearOfFixed`. The player drags a rectangle; `buildPlan`
  (`js/PlayerInteract/Build.js:76`) builds it, capped at `SHAPE_MAX` = 48
  (`js/lib/Shape.js:64`). `buildVerdict` (`Build.js:87`) returns `big` above
  `max`, `room` when `fits` fails. `padPlace` (`Pad.js:3`) stores the
  bounding box of the first and last plan cell.
- **Rule.** `clearOfFixed` (`Build.js:94`) rejects only out-of-window cells and
  `FIXED` materials (structures, unbreakable rock). Sand, ore, liquid and loose
  rock are all accepted, and nothing above the rect is checked.
- **Preview.** `drawBuildPreview` (`Build.js:178`) runs only while dragging
  (`buildFrom` set), tinted `aqua` / `dangerSoft` by the verdict. On hover the
  generic 1-cell ghost is drawn (`js/render.js:389`), whose tint also depends on
  reach and the single cell under the cursor.
- **Look.** `drawCargoPad` (`Pad.js:14`) strokes a pulsing dashed outline and
  a floor strip, both `uiRgba('sand', ...)` (`Pad.js:26`, `Pad.js:33`). The
  drone and its tractor beam are also sand-coloured (`render.js:256`,
  `render.js:261`).
- **Use.** `sweepPad` (`js/market.js:42`) counts and removes cargo cells inside
  the rect; `callDrone` (`market.js:74`) and `tickMarket` (`market.js:99`)
  need `padInWindow()`. HUD status at `js/hud.js:83`, `hud.js:103`;
  `first_pad` event at `js/game.js:8`. Message `msg.padBig` (`js/lang/en.js:91`)
  says "96 cells at most".

## Proposed behaviour

1. **Fixed size.** The block is `PAD_W` x `PAD_H` cells, one code constant pair
   in `Pad.js`, replacing `PAD_MAX`. The value is still open.
2. **Placement.** The block is anchored to the cursor (see open questions for
   which point). One click places it; dragging has no effect on the shape.
   Placing a new pad still replaces the old one.
3. **Rule.** The plan fits when both hold:
   - every block cell is in the window and empty;
   - for every column of the block, every cell from the row above the block up
     to row 0 is empty.
   Nothing else decides the verdict: no size check, no reach.
4. **Preview.** While a pad is the active building, the full block is drawn at
   the cursor on hover, tinted ok/bad by the rule above alone. It replaces both
   the drag preview and the 1-cell ghost for the pad.
5. **Colour.** A new UI token (working name `pad`) in `UI_NAMES` / `UI_BASE`
   (`js/settings.js:20`, `settings.js:33`), so it also goes through the
   colour-vision filters. Its hue must be far from `sand` [224, 168, 82] and
   from the ok/bad preview tints, so a placed pad is not mistaken for a valid
   preview.
6. **After placement** the pad stays a zone, as today: cargo falls into it and
   `sweepPad` takes it. The rule is checked only at placement (see open
   questions).

Cleanup that falls out: `PAD_MAX`, the `max`/`big` spec fields, the `big`
branch of `buildVerdict` and `finishBuild`, and `msg.padBig` in every
`js/lang/*.js` lose their only user and are removed. The pad no longer offers
shapes, so the shape bar (`hud.js:158`) and shape key (`js/input.js:58`) hide
for it through the existing "fewer than two shapes" checks.

## Core and shell

| Part | Layer | Where |
|---|---|---|
| Block cells for an anchor point | core | `Pad.js` core path (or `world.js`) |
| Fit rule: empty block, open columns | core | `Pad.js`, next to `clearOfFixed` |
| `padPlace`, `setCargoPad`, `cargoPad` | core | `Pad.js`, `world.js` |
| Click-to-place flow in `buildUse` | mixed | `Build.js` |
| Hover preview, pad and drone drawing | shell | `Pad.js`, `Build.js`, `render.js` |
| `pad` colour token | shell | `settings.js` |

The fit rule reads only `mat`, `W`, `H` and the material tables, so it is
testable headless through `test/core.js`.

## Affected files and functions

- `js/PlayerInteract/Buildings/Pad.js`: `PAD_MAX` -> size constants; new fit
  function; `padPlace`; `drawCargoPad` colour; `regBuilding` spec.
- `js/PlayerInteract/Build.js`: `buildPlan`, `buildVerdict`, `finishBuild`,
  `buildUse`, `drawBuildPreview` gain a fixed-block path; `big` handling goes.
  `clearOfFixed` stays for `Wall.js`.
- `js/world.js`: `setCargoPad` may take the anchor instead of a rect;
  `padLocal`, `padInWindow` unchanged.
- `js/market.js`: no logic change; `sweepPad` keeps reading the rect.
- `js/render.js`: `drawGhost` skipped for the pad; drone colour if agreed.
- `js/settings.js`: new `pad` token.
- `js/lang/*.js`: drop `msg.padBig`; maybe reword `tool.pad.desc` and
  `msg.padDone` ("marked" -> "built").

## Sliding window

- `cargoPad` stays in world X, so chunk shifts need nothing new; with a fixed
  size `padInWindow` keeps its meaning.
- The fit rule uses local coordinates and only cells inside the window, so a
  pad can only be placed fully inside the window. Today the window is the full
  world height, so row 0 is the real top and "clear to row 0" is "clear to the
  sky". When the vertical axis lands, the column check must reach above the
  window (stored or generated chunks) or treat the window top as sky.
- The frozen strip (`EDGE_FREEZE`) is never on screen, so the player cannot
  aim into it; no extra rule.
- A drone in flight when the pad leaves the window still aborts and refunds
  (`market.js:105`). Unchanged.

## Edge cases

- Cursor near the window edge: block partly out of bounds -> bad tint, no place.
- Gas (smoke, steam) in the block or the column: counts as empty or not,
  depends on the definition of empty (open question).
- Re-placing over the current pad: the old zone usually holds cargo, so the
  rule rejects it unless empty; moving a full pad is impossible by design.
- Replacing the pad while the drone is in flight: delivery at half-trip uses
  whatever pad exists then. Same as today.
- Sandbox room (`js/sandbox.js`): check that it has open sky where a pad can go.
- Overhangs one cell wide over part of the block: one blocked column rejects
  the whole block.
- Player standing in the block or column: the player is not a cell, so he does
  not block placement.

## Open questions

1. Block size `PAD_W` x `PAD_H`: value, and in cells or `SIZE.m(...)` like
   the belt and wall?
2. "Empty": `VOID` only, or `OPEN` (void or gas) like `beltFits`?
3. Anchor: cursor at the block's bottom centre (natural "set it down"), or
   its top-left like the drag rect today?
4. Must the block also rest on something solid below, or may it float in the
   air?
5. Is the rule checked only at placement, or does the pad stop working
   (drone refuses) when the sky column later fills up?
6. Colour: which hue? Also recolour the drone and its beam, which are sand
   today?
7. Keep the pad a zone (rect over cells, cargo inside), or make it cells of a
   pad material per the world model? A zone is simpler and cargo must occupy
   those cells; this note assumes a zone.
8. Does the pad get a price or unlock like other buildings, or stay free?

## Decisions (approved 2026-10-18)

1. Size is a constant built with `SIZE.m(...)`; the value is tuned in the browser.
2. Empty means `OPEN` (void or gas), as in `beltFits`.
3. The block is anchored bottom-centre on the cursor.
4. The block must rest on solid ground.
5. The sky rule holds all the time: if the column fills later, the drone refuses and says why.
6. New colour token `pad` (aqua); the drone and its beam use it too.
7. The pad is cells: a floor row of a `pad` material, cargo counted above it (world model: everything is a cell).
8. Free to place; one pad.
