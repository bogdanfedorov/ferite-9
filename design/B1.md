# B1 — Wall placement

Status: docs. Feedback 9, 11 (TASKS.md).

## What and why

A wall is something the player draws into open space. Today it is a paint
brush: it overwrites sand, coal, ore and water, which destroys resources, and
it refuses to be drawn over an existing wall, so extending or closing a wall
needs pixel-exact drags. The new rule:

- empty or gas cell: becomes wall;
- wall cell: skipped, left as it is;
- any other cell (powder, liquid, solid, belt, bedrock) or out of bounds: the
  whole plan is invalid and nothing is placed.

A plan is valid when every cell is open or wall. Cost, if any, counts only
the cells that change.

## Current behaviour

- `buildPlan` (`js/PlayerInteract/Build.js:76`) turns the drag into shape cells
  and widens each by the building size with `thickenCells`
  (`js/sizes.js:10`). Wall size is `SIZE.m(0.1)` square
  (`Buildings/Wall.js:9`), so every shape cell becomes a 10x10 block; the
  blocks are de-duplicated.
- `buildVerdict` (`Build.js:87`) returns `big`, `room` or `ok`; `room` comes
  from `spec.fits(plan)`.
- Wall uses `fits: clearOfFixed` (`Wall.js:19`). `clearOfFixed`
  (`Build.js:94`) rejects a plan if any cell is out of bounds or `FIXED`.
  `FIXED` is `state === structure || hardness < 0`
  (`js/materials.js:191`): bedrock, belt and wall. So:
  - wall over wall fails (feedback 11);
  - sand, coal, ferrite, water, lava, rock, ore seam all pass.
- `wallPlace` (`Wall.js:3`) calls `setCell(x, y, WALL_ID)` on every plan cell
  (`js/world.js:225`), overwriting whatever was there (feedback 9).
- `finishBuild` (`Build.js:128`) runs verdict, then `spec.place`, then returns
  `spec.done` (`msg.wallDone`) or `BUILD_REPORTS.room` (`msg.beltRoom`).
- The preview (`drawBuildPreview`, `Build.js:178`) tints the plan with
  `buildVerdict`, so it already follows whatever `fits` says.
- Cost: `cost: 120` (`Wall.js:11`) is a one-time unlock price.
  `pieceCost` (`Registry.js:34`) is read only by `buyTool`
  (`Toolbelt.js:54`) and the toolbelt card. Placing cells charges nothing;
  there is no per-cell cost anywhere today.
- `clearOfFixed` is also the `fits` of Pad (`Buildings/Pad.js:49`). Belt has
  its own `beltFits` (`Belt.js:20`), which already requires `OPEN` cells.

## Proposed behaviour

Each plan cell falls into one of three classes, decided by its material:

| Class | Condition | Effect |
|---|---|---|
| new | in bounds, `OPEN[m]` (void or gas: empty, steam, fire, smoke) | becomes wall |
| kept | in bounds, `m === WALL_ID` | untouched |
| blocked | anything else, or out of bounds | plan invalid |

- `fits` for wall: no cell is blocked. A wall-specific `wallFits` in
  `Wall.js`, next to `wallPlace`. `clearOfFixed` stays as it is for Pad.
- `place`: `setCell` only on new cells. Kept cells keep their `shade`,
  `dmg`, `temp`, so an existing wall does not flicker or heal when redrawn.
- Verdict, reports and preview need no new branches: an invalid plan is
  `room` as today, and the preview tints red through `buildVerdict`.
- Gas in a new cell is deleted, as it is today. Gas mass is not conserved;
  this matches how belts are placed.

## Core and shell

- Core (core paths of the Mixed files `Build.js`, `Buildings/Wall.js`):
  cell classification, `wallFits`, `wallPlace`, the new-cell count and any
  charge. All run headless and are what the unit tests check.
- Shell: the preview tint and the notice text. No change needed unless the
  preview should mark kept cells differently (open question 3).
- `thickenCells` (`sizes.js`, core) is unchanged by the rule but decides which
  cells are classified; see edge cases.

## Edge cases

- Plan entirely over existing wall: valid, zero new cells. Today it is `room`.
  What is reported is Q2.
- Plan partly over wall, partly open: valid; only the open part is placed.
- One sand grain or water drop inside a large plan: whole plan invalid. The
  10x10 thickening makes this frequent near the ground.
- Solid rock, ore seam, coal seam, glass, iron: blocked. Today they are
  overwritten; this is a behaviour change beyond feedback 9, but it is what
  "any other material" says.
- Belt cells: blocked (structure, not wall), as today.
- Fire and steam: gas, so wall replaces them. A wall drawn into fire gets
  the fire cell's temperature, because `setCell` does not reset `temp`.
- Out of bounds: blocked, as today. `thickenCells` keys cells by `y * W + x`
  before any bounds check, so a cell at `x = W` and one at `(0, y + 1)` share a
  key and one is dropped. A plan touching the right edge can lose its
  out-of-bounds cell and pass. Pre-existing, not caused by B1; noted because
  B1 touches the same path.
- Player and loose objects (`objects.js`) inside new cells: no check today;
  the wall is drawn over them. Unchanged by B1 (Q4).
- Sand falling into the plan between preview and release: the verdict is
  recomputed in `finishBuild`, so the release decides, not the preview.

## Open questions

1. Cost. There is no per-cell charge: 120 is a one-time unlock. Either
   (a) walls stay free to place and the rule "charge only new cells" holds
   trivially, or (b) a per-cell price is introduced (a new spec field, charged
   in `finishBuild` for the new-cell count, with a refusal when money is
   short). (b) is a new economy feature, not a fix; which one?
2. A plan that is all kept cells: silent no-op, `msg.wallDone`, or a new
   "nothing to build" report? Proposal: same report as `nothing` for erase
   (`msg.nothingToRemove` has no sound), with a build-side text.
3. Should the preview show kept cells in a third tint, so the player sees what
   will actually be built? Shell-only, can be split off.
4. Should the player's own cells or objects block a wall cell? Out of scope
   unless wanted here.
5. Solid rock blocking a wall: intended, or should solids count as "kept"
   like wall (a wall built flush against a rock face)? Thickening makes this
   matter for walls drawn along terrain.
6. Fix the `thickenCells` edge aliasing in B1 or file it separately?

## Decisions (approved 2026-10-18)

1. No per-cell price; walls stay free to place.
2. A plan made only of existing wall: silent.
3. No third preview tint.
4. Solid rock blocks a wall.
5. The `thickenCells` right-edge key collision is fixed in B1.
