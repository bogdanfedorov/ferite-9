# D5 — Pickup zone status view

Status: docs. Feedback 16. Depends on A1 (pickup zone as a fixed-size building).

## What and why

While building a factory the player wants to know what they have right now:
how much of each material lies in the pickup zone and what it would sell for.
Today the right-hand panel answers a different question first — what every
good costs — and the cargo count is a small number squeezed between the name
and the price. Players read it as a price list and find it noisy.

The fix splits two views:

- **Cargo** — always visible: money, what lies in the zone(s) by material, the
  value at current prices, the drone button.
- **Market** — on demand: the price of every good and how far it has decayed.

Cargo is shown the way strategy games show stock: fixed slots, one per good,
count first. It must work for one zone today and for many zones once A1 lands.

## Cost of the sweep

`sweepPad(false)` reads `pad.w * pad.h` cells: at most 96 today. After A1 a
zone is a fixed block of `ZONE_W * ZONE_H` cells, and Z zones cost
`Z * ZONE_W * ZONE_H` reads plus one small object. Ten 12×8 zones are under
1000 array reads — noise next to `simulate()`, which touches every cell every
step. Per frame is affordable; the DOM write is the real cost, and it is
already throttled by `setText`/`setVal` and the 6-frame HUD tick.

Decision: no cache, no new state. The shell calls a pure core function at the
HUD cadence (10 Hz at 60 fps). A cached `market.hold` refreshed in
`tickMarket` would add state that can go stale and must be reset; it is worth
it only if zones grow by orders of magnitude, which A1 rules out.

## Layout options

### Option A — top resource strip (recommended)

A thin bar in the top centre (grid column 3, row 1), the slot strategy games
use for stock. Money first, then one fixed slot per good, then the total and
the drone button. Slot order is `GOODS` order and never moves; an empty slot
is dimmed, not removed, so the eye finds iron in the same place every time.

```
┌──────────┐ ┌──────────────────────────────────────────────────────────────────┐ ┌──────────┐
│ MODULE   │ │ $214 │ ▪gravel 32 │ ▪sand – │ ▪coal 12 │ ▪ferrite 40 │ ▪iron 6 │ ▪glass – │
│ sol_1.01 │ │      │   $64      │         │   $96    │   $448      │  $228   │          │
│ hp  ███▒ │ │                          in zone · $836   [ DRONE FOR $10 ]  [ MARKET P ] │
└──────────┘ └──────────────────────────────────────────────────────────────────┘ └──────────┘
```

Each slot: colour swatch from the material, count (large), value at current
price (small). Narrow screens (`max-width:980px`) drop the names and keep
swatch + count, as `.ub-label` already does for buttons.

The **Market** button (and a hotkey) toggles the price view: a right-stack
panel, hidden by default, not a modal — the game keeps running and nothing is
darkened (same rule as D4).

```
                                                              ┌──────────────┐
                                                              │ MARKET       │
                                                              │ gravel    $2 │
                                                              │ ██▒▒▒▒▒▒▒▒▒▒ │
                                                              │ sand      $3 │
                                                              │ ███▒▒▒▒▒▒▒▒▒ │
                                                              │ …            │
                                                              │ glass    $58 │
                                                              │ ███████████▒ │
                                                              └──────────────┘
```

Many zones: the strip shows the sum over all zones. Hovering or clicking a
slot opens a small drop-down with the count per zone (zone 1, zone 2, …),
which also answers "which zone is filling".

Pros: always visible without covering the play field's sides; matches the
genre; frees the right column for the Market view and later panels.
Cons: competes with `comms` and the probe chip for top space; needs a
compact narrow-screen form.

### Option B — pinnable cargo list (right column)

The right panel stays where it is but becomes **Cargo**: rows only for goods
that are present, count and value per row, total and drone button at the
bottom. A tab row in the header switches to **Market** (today's price list).
With several zones, each zone is a collapsible group with a pin; pinned
groups stay expanded, the rest collapse into one summary line.

```
                                                              ┌──────────────┐
                                                              │ CARGO │market│
                                                              │ $214         │
                                                              │ ▼ zone 1  📌 │
                                                              │ ferrite 40   │
                                                              │        $448  │
                                                              │ gravel  32   │
                                                              │         $64  │
                                                              │ ▶ zone 2 $324│
                                                              │ in zone $836 │
                                                              │[DRONE FOR $10]│
                                                              └──────────────┘
```

Pros: smallest change to markup and CSS; per-zone detail is first-class.
Cons: rows appear and disappear, so positions jump; cargo and prices still
share one panel, which is the thing players disliked; pinning adds state the
shell must persist or lose.

### Recommendation

Option A. It answers "what do I have" at a glance with stable positions, keeps
prices out of the way until asked for, and the per-zone drop-down covers
A1's many zones without pinning state. Option B's grouping is the fallback if
top space proves too crowded.

## Core and shell

Core computes, shell draws. No new world state.

Core (`js/market.js`):

- `zoneCargo(zone)` — counts by cargo group for one zone, without taking. This
  is `sweepPad(false)` generalised from the single `cargoPad` to a zone rect;
  `sweepPad(true)` keeps its taking path on top of it.
- `cargoSummary()` — `{ total: counts, zones: [counts…], value }` over every
  zone, `value = payoutOf(total)`. One call per HUD tick.
- `payoutOf`, `priceOf` unchanged. Per-slot value is `count * priceOf(good)`.

Until A1 lands, "every zone" is the one `cargoPad`; the function shape does not
change when A1 turns it into a list.

Shell (`js/hud.js`, `index.html`, `style.css`):

- `buildCargoStrip()` / `updateCargoStrip()` replace the cargo half of
  `buildMarketPanel` / `updateMarketPanel`: fixed slots from `GOODS`, values
  from `cargoSummary()`, money, total, drone button (`droneLabel` reused).
- `buildMarketPanel` / `updateMarketPanel` keep only the price half: name,
  price, decay bar; skip the update while the panel is hidden.
- A Market toggle: button in the strip plus a key binding, so it is mouse
  reachable (D6).

Tests (step 3) cover the core only: counts per zone, sum over zones, value at
a given `market.age`, and that the status call never changes a cell.

## Open questions

1. Strip (A) or list (B)? Recommendation is A.
2. Empty slots: dimmed fixed slots (recommended) or only goods present?
3. Slot shows count and value, or count only with value on hover?
4. Market key: `P`? `M` is mute.
5. Does the Market view open by default for a new player (prices teach the
   decay), or stay hidden until asked?
6. Show a trend per slot (▲ filling / ▼ draining since last tick)? Needs the
   previous summary kept in the shell; small, but new behaviour.
7. With many zones and one drone: does the drone serve all zones in one trip
   (then the total is what it pays) or one chosen zone? This is A1's call,
   and it decides whether the strip total or a per-zone figure drives the
   drone button and its `worth` pulse.
8. Should money also leave the strip and stay where the inventory shows it
   (`#inv-money`), or is the strip its single home in play?

## Decisions (approved 2026-10-18)

1. Option A: top strip.
2. Empty goods stay as dimmed fixed slots.
3. A slot shows count and value.
4. Market opens with `P`.
5. The Market view is hidden until asked for.
6. No trend arrows now.
7. One pad, one drone (A1).
8. Money lives only in the strip.
