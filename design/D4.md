# D4 — Build menu: tile grid plus detail panel

Status: docs. Feedback 14, 15 (first playtest, 2026-10-17).

## What and why

The **E** menu is where the player buys tools and buildings, levels them up and
puts them into the hotbar. Playtest feedback: the menu is cramped, a locked
tool shows only a price, so you pay before you know what you get. The menu also
darkens the whole screen, so your money is hidden while you decide what to
buy, and it carries a lot of text that tells the player nothing.

The new menu is one panel with two halves: a grid of square tiles on the left
(icon and name), and a detail panel on the right for the tile you clicked
(what it does, price, Buy or Upgrade). Nothing behind the panel is dimmed or
blurred; the market panel with the money stays readable.

This is a shell change. The core API in `Toolbelt.js` (`buyTool`,
`upgradePiece`, `pickForSlot`, `placePicked`, `assignSlot`) already models
buying, levelling and slot assignment and stays as it is.

## Current behaviour

### Structure

- Markup: `index.html:75-82`. `#inventory` is a `.screen` overlay holding one
  `.screen-card.inv-card`: a kicker line (`inv.kicker` · `#inv-money`), a note
  (`inv.note`), the card grid `#inv-tools`, and `#inv-slots`, a copy of the
  hotbar.
- Overlay: `.screen` (`style.css:535-543`) is `position:fixed; inset:0`, a
  radial dark gradient and `backdrop-filter:blur(2px)`, `z-index:20`. It covers
  and dims the whole HUD, including the money in the market panel
  (`index.html:58`).
- Card grid: `style.css:500-531`, `auto-fill` columns of at least 150 px; each
  card is a text row, not a tile.
- Cards are built once by `buildToolbelt` (`Toolbelt.js:180-204`), called from
  `game.js:306`, one `toolCard` (`Toolbelt.js:114-131`) per entry of
  `PIECE_IDS`, in script order (`index.html:231-236`): drill, hand, pad,
  ignite, belt, wall.
- A card holds: `.sicon` (glyph from `hud.icon`), `.sname` (`hud.name`),
  `.scost`, `.slvl`, and `.sup`, a clickable span nested inside the card
  button for the upgrade (`Toolbelt.js:125-129`, `stopPropagation`).

### Pieces

| id | price | levels | open at start |
|---|---|---|---|
| drill | — | — | yes |
| hand | — | — | yes |

`resetToolbelt` (`Toolbelt.js:6-15`) opens every piece without `cost`.
`levels` exists only on the belt (`Buildings/Belt.js:134`); `interval` is the

and 60 moves per second.

### Card states (`renderCard`, `Toolbelt.js:153-169`)

| state | class | `.scost` shows | look |
|---|---|---|---|
| locked, affordable | `locked` | `$price` | opacity .8, price in sand (`style.css:497-498`) |
| locked, too poor | `locked poor` | `$price` | opacity .38, `cursor:not-allowed` (`style.css:527`) |
| open | — | `hud.desc` | normal |
| open, current tool | `active` | `hud.desc` | sand top line |
| open, picked for a slot | `picked` | `hud.desc` | sand outline |

Open pieces with levels add `.slvl` "lv N" and, if a next level exists,
`.sup` "▲ lv N+1 · $cost" (`upgradeLabel`, `Toolbelt.js:147-151`), red when
too poor.

A locked card never shows its description: the player sees only icon, name
and price.

### Interactions (`game.js:41-69`, `input.js:87-107`)

- **E** toggles the menu (`toggleInventory`, `game.js:64-69`); it clears the
  pick and redraws. Opening it pauses the game (`OVERLAYS`, `game.js:24`,
  `toggleScreen` `game.js:178-186`). **Esc** or **E** closes it
  (`onInventoryKey`, `input.js:104-107`).
- **Click a locked card** → `invTool` → `buyTool` immediately, no confirmation
  (`game.js:55-58`, `Toolbelt.js:54-58`). `spend` refuses with a notice
  `msg.cantAfford` if money is short; otherwise money drops, `openTool` puts
  the piece into the first free hotbar slot, and a notice `msg.bought` plays.
- **Click an open card** → `pickForSlot(name)` sets `toolbelt.picked`
  (`Toolbelt.js:79-81`). It does **not** change `game.tool`; the card only gets
  the `picked` outline.
- **Click a slot in `#inv-slots`, or press 1–8** → `invSlot` → `placePicked`
  (`Toolbelt.js:83-91`): with a pick, `assignSlot` puts it there (swapping
  with the slot it came from) and clears the pick; without a pick, the slot's
  own tool becomes the pick, so two slot clicks swap two slots.
- **Click `.sup`** → `upgradePiece` (`Toolbelt.js:60-66`): spends, raises
  `toolbelt.level`, notice `msg.upgraded`.
- Redraw: `renderToolbelt` (`Toolbelt.js:171-178`) runs on every pick, and
  from the frame loop whenever `market.money` changes (`game.js:172`).

The real hotbar (`#hotbar`, `index.html:72`) stays under the overlay and
cannot be clicked; `#inv-slots` exists only because of that.

## Proposed layout

One panel, centred horizontally, sitting above the hotbar. No backdrop: the
element is the panel itself, not a full-screen layer, so the market panel
(money) and the hotbar around it stay visible and undimmed.

```
                                                     ┌ market ─────────┐
                                                     │ $  312          │
                                                     │ ...             │
                                                     └─────────────────┘
   ┌────────────────────────────────────────────────────────────┐
   │ ┌──────┐ ┌──────┐ ┌──────┐  │  »  Belt                      │
   │ │  ▼   │ │  ◐   │ │  ▭   │  │                               │
   │ │Drill │ │ Hand │ │Pickup│  │  Carries loose material       │
   │ └──────┘ └──────┘ └──────┘  │  sideways, one row at a time. │
   │ ┌──────┐ ┌══════┐ ┌──────┐  │                               │
   │ │  ✦   │ ║  »   ║ │  ▦   │  │  Speed   20 moves/s           │
   │ │Ignit.│ ║ Belt ║ │ Wall │  │                               │
   │ │ $60  │ ║ $240 ║ │ $120 │  │  ┌─────────────────────────┐  │
   │ └──────┘ └══════┘ └──────┘  │  │       Buy · $240        │  │
   │                             │  └─────────────────────────┘  │
   └────────────────────────────────────────────────────────────┘
        ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┐
        │1 Dr │2 Ha │3 Pi │4    │5    │6    │7    │8    │   ← real #hotbar
        └─────┴─────┴─────┴─────┴─────┴─────┴─────┴─────┘
```

- **Tile**: square, icon large on top, name below. A locked tile adds its
  price under the name and is dimmed; a too-poor locked tile shows the price
  in red. Nothing else on a tile.
- **Detail panel**: icon and name, the description sentence, the piece's stat
  if it has levels, and one action button: **Buy · $price** for a locked
  piece, **Upgrade · $cost** with "stat now → next" for an open piece with a
  next level, nothing for an open piece at max level or without levels.
- **Slots**: the real `#hotbar` is the assignment target while the menu is
  open; `#inv-slots` is removed (open question 2).
- Narrow screens (< 640 px): the detail panel goes under the grid; still one
  panel.

## States and interactions

Menu state is the existing `toolbelt.picked` plus one shell value, the tile
shown in the detail panel:

```
menu   = closed | open(shown)
shown  = piece id | null
picked = toolbelt.picked  (open piece id | null)
```

`shown` is shell state (which tile the detail panel describes); `picked` stays
the core value. Both reset to `null` when the menu opens, as `toggleInventory`
already does for `picked`.

| Event | Locked piece | Open piece |
|---|---|---|
| click tile | `shown = id`; `picked = null` | `shown = id`; `pickForSlot(id)` (as today) |
| click Buy | `buyTool(id)`; on success `pickForSlot(id)` so the next slot click places it | — |
| click Upgrade | — | `upgradePiece(id)` |
| click hotbar slot / 1–8 | `invSlot(i)` (as today) | `invSlot(i)` (as today) |
| E / Esc | close | close |

- One click on an open tile both shows it and picks it, so tile → slot is
  still two clicks, as today. Buying no longer happens on the tile click; it
  needs the Buy button. That is the only extra click, and it is the point:
  you read before you pay.
- After a buy, `openTool` already drops the piece into the first free slot;
  picking it as well lets the player move it in one more click.
- Buy and Upgrade are disabled (not hidden) when money is short; the price on
  the button turns red. No `spend` call happens, so no `msg.cantAfford`.
- The game stays paused while the menu is open (`OVERLAYS` unchanged), so
  money does not move under the open menu (open question 3).

Failure outcomes: none new. `buyTool` and `upgradePiece` keep their own
guards (`spend`, `toolOpen`, `nextLevelOf`); a disabled button is a shell
convenience, not the guard.

## Detail stats

Only the belt has levels. Its stat shown to the player is speed in moves per
second, `60 / interval` (20, 30, 60). The level number itself is not shown.
The stat name and unit come from the piece spec (a `stat` key next to
`levels`), so a future levelled piece adds its own without new menu code
(open question 4).

## Open questions

1. Name: the menu holds buildings too. Keep "Tools", rename to "Build", or show
   no title at all?
2. Drop `#inv-slots` and assign through the real hotbar while the menu is open?
   It removes a duplicate row, but makes hotbar clicks mean "assign" while the
   menu is open and "select" otherwise.
3. Keep the game paused while the menu is open? Undimmed and paused can look
   like a freeze; unpaused means the world (and a drone sale) runs while you
   shop.
4. Should clicking an open tile also select it as the current tool
   (`selectTool`)? Today it only picks it for a slot; the task text says "one
   click both selects and lets you assign", which the code does not do now.
5. Belt speed shown as "moves/s", as a multiplier (×1, ×1.5, ×3), or in m/s
   via `SIZE`?
6. Click outside the panel: close the menu, or do nothing?

## Decisions (approved 2026-10-18)

1. No title.
2. Drop `#inv-slots`; assign through the real hotbar.
3. The game is not paused while the menu is open.
4. Clicking an open tile makes it the current tool and lets you assign it.
5. Belt speed is shown as a multiplier (×1, ×1.5, ×3).
6. A click outside the panel closes the menu.
7. The menu open and close buttons (from D6) are built here.
