# C3 — Hand lifts a resource out; it spills on release

Status: docs. Feedback 19 (first playtest, 2026-10-17).

## What and why

Playtest: the Hand only takes from the top. A resource under another layer
cannot be pulled out, so a heap is dug one surface skin at a time and digging
takes forever.

The cause is that a grabbed lump is a physical body in the grid. It has to
travel from where it was taken to the cursor by pushing through every cell in
between. Under a layer there is nowhere to push to, so the lump does not move,
and on release it goes back where it came from.

New mechanic, decided by the user: grabbing a resource empties the cells it
came from and the resource is held *in hand*, outside the world. While the
button is held nothing else is moved. On release the load spills into free
space near the cursor. What lies above the emptied cells falls into the hole
by ordinary physics — that is the digging.

### Why upper layers block lower ones

The held lump moves through the grid, cell by cell:

| Where | What |
|---|---|
| `js/objects.js:293-298` | held: spring `OBJ_SPRING` toward the grip, damping `OBJ_DAMP`, speed cap `OBJ_MAXV` (`:304-307`) |
| `js/objects.js:260-285` | `moveObject`: sub-steps of 0.25 cell; a blocked axis zeroes that velocity |
| `js/objects.js:163-171` | `objPass` (held): fails if any target cell is `RIGID` (solid or structure); otherwise every target cell must be shoved |
| `js/objects.js:141-161` | `shoveCell`: an open cell passes; a powder or liquid cell must move into an **open** cell found by `shoveTarget` — the four neighbours, then `openNear` radius 2..`SHOVE_R` (3) |

So a lump taken from under a layer must shove every cell of that layer into
empty space within 3 cells. In a packed heap the only empty space is the hole
the grab itself left, and `simulate()` runs before `stepObjects`
(`game.js:148-150`), so powder above has already fallen into that hole. The
lump does not move. Any rock or wall in the way stops it outright.

Release puts the lump back at its own position (`releaseObject`,
`objects.js:120-128` → `dropObject`, `:199-218`): each cell goes to the same
spot via `placeCell` (`:175-187`: open, or shove the occupant, else `openNear`
radius 1..`DROP_R` = 14), else `swapCell` (`:189-197`) trades places with a
movable cell. A cell that finds nowhere stays in an unheld object that falls
under `OBJ_GRAV` and retries when it comes to rest (`:316-322`).

Net effect: a lump grabbed under a layer is put back where it was. Only the
top layer of a heap can actually be carried away. The grab is also one
material at a time, so a mixed heap is peeled per material.

### Other current details

- A held lump shoves powder and liquid out of its path (`objPass`): the hand
  *does* move other things while held.
- Held cells cool toward 22 °C at `0.0015` per frame (`objects.js:311-314`).
  The player takes no heat from what it carries.
- Window shift: `shiftObjects` (`objects.js:347-364`) shelves an object that
  leaves the window; `shelveObject` (`:326-332`) clears `heldObject`, so the
  load is silently dropped onto the shelf.
- Death: `respawn` releases after the window has followed the spawn, so the
  lump is dropped wherever its stale coordinates point.
- Drawing: `drawObjects` (`js/render.js:265-306`) draws the held lump lighter,
  with a line from the player; `drawGrabHint` (`Hand.js:14-37`, shell) lights
  up the `grabPick` cells within `REACH` of the cursor.
- `onObjectImpact` (`objects.js:246`) is declared nowhere.

## Proposed behaviour

### Model

```
handLoad  null | [{ mat, temp }]        one entry per lifted cell
```

The load has **no position**. It is not in `objects`, has no velocity and
never touches the grid while held. One material per load, as today.

States and transitions:

| State | Event | Outcome |
|---|---|---|
| empty | press, grabbable cell in reach | pick cells (`grabTargetAt` + `grabPick`), copy `{mat, temp}`, set them to `VOID_ID`; `handLoad` = copies; `notice('grab', null)` |
| empty | press, nothing grabbable | `notice(null, t('msg.nothingToGrab'))`; stays empty |
| holding | press | impossible: press only fires on button down, and release happens on button up |
| holding | frame | load cools as today; nothing in the world is moved by the hand |
| holding | button up, or tool switched away | `spillLoad(clampToReach(cursor))` → empty |
| holding | player dies | `spillLoad` at the player's position before respawn → empty |

`spillLoad(x, y)`: for each entry, put it in the nearest open cell (`OPEN`:
void or gas) around `(x, y)`, searching rings outward up to `DROP_R`. No
shoving, no swapping: a spill never displaces what is already there. It
returns what did not fit (see open question 1).

Because the load has no position, digging works at any depth within reach:
the cells are lifted, whatever lay above falls into the hole under normal
`simulate()` rules, and the load lands where the player points.

### What goes away

The held branch of the object physics has no caller left: the spring
(`OBJ_SPRING`, `OBJ_DAMP`), `objPass`'s shove path, `takeObject`/`makeObject`
with `held: true`, `heldObject`, the held drawing and tether line, and
`swapCell` if remainders no longer use it. Unheld objects stay only if open
question 1 keeps them; otherwise `objects.js` shrinks to grab-pick plus
`spillLoad`.

## Core and shell

- **Core** (`objects.js`): `handLoad`, `grabLoad(x, y)`, `spillLoad(x, y)`,
  cooling of the load. All headless-testable: grab empties exactly the picked
  cells, spill conserves per-material counts, spill never overwrites a
  non-open cell.
- **Mixed** (`Tools/Hand.js`): `handPress` calls the core grab and `notice`.
  `drawGrabHint` stays shell code.
- **Shell** (`game.js`, `render.js`): release on button up or tool switch,
  spill on death before `followWindow`, drop sound, drawing the load at the
  clamped cursor and the spill preview.

## Edge cases

- **No free space on release.** Cursor inside packed rock or a full heap and
  no open cell within `DROP_R`. Must not destroy matter. See open question 1.
- **Liquid or hot material.** Liquids are not grabbable today and stay so
  unless decided otherwise (question 3). Hot powder (slag, ember, iron_scrap
  fresh from a furnace) keeps its `temp` in the load and cools as today; it
  spills hot and can ignite what it lands next to. No damage to the player.
- **Window shift while holding.** The load has no coordinates, so a shift
  cannot shelve or lose it. `spillLoad` takes local coordinates computed in
  the same frame, after `followWindow`.
- **Player dies while holding.** Spill at the death position before
  `followWindow` moves the window to the spawn; today the order
  (`game.js:89-92`) loses the death position first.
- **Reach limit.** Grab and spill points are both `clampToReach(cursor)`.
  Grabbing still needs no line of sight (you can lift through rock within 32
  cells). The spill search may place cells up to `DROP_R` past the reach
  circle when the spot is crowded.
- **Grab cap.** `OBJ_MAX` no longer limits grabs because the load is not an
  object.
- **Tool switch mid-hold.** Same as button up (`game.js:135`).
- **Sandbox / pause.** No change; the load waits while paused.

## Open questions

1. No room on release: keep the remainder in hand (release refused, notice),
   widen the search without limit, or drop it as a falling unheld object as
   today? The last keeps `objects`, `swapCell` and the shelf alive.
2. How much is lifted per grab: one cell (as the task text says), or the
   current `grabSize²` same-material flood fill from the settings slider?
3. Should liquids become grabbable now that the load no longer needs to
   push through the grid?
4. Should grabbing require line of sight from the player, so lifting through
   a rock wall is not possible?
5. Is there any visual of the load while held (lump at the cursor, counter by
   the cursor, nothing), and should the spill cells be previewed?
6. On death: spill at the death spot, or lose the load?

## Decisions (approved 2026-10-18)

1. No free space on release: the rest stays in hand and spills as soon as space appears.
2. Grab amount stays `grabSize²` from the slider.
3. Liquids are not grabbable for now.
4. No line-of-sight rule.
5. While holding: a lump at the cursor and a cell count.
6. On death the load spills at the death spot.
